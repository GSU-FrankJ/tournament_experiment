# E.1 结果：q=50 的单次成功概率 p

**20 条全部完成（rc=0，整批 551 s）。E.1 单批 discovery 19/20 = 95.0%，
但 19 个候选里有 2 个在最终认证失败，端到端 17/20 = 85.0%。
与 confirmation 合并后 n=30：discovery 26/30 = 86.7% [70.3, 94.7]，
conditional certification 24/26 = 92.3%，端到端 24/30 = 80.0%。**

协议为 `FINAL_T2_PROTOCOL_20260922.json`，预登记为 `experiments/two_stage_E1_q50_p_20260923/PREREGISTRATION.md`，
两者都在启动前冻结。seeds 10121–10140，与 10001–10020、10101–10120 均不相交。
20 条 run 的 `config.record` 与 manifest 逐条精确一致，`issues` 为空。

## 二、与 confirmation 的关系：70% 是一次运气差的抽样

| 批次 | discovery | 95% Wilson |
| --- | --- | --- |
| confirmation（N=10 预登记，**结果不修改**） | 7/10 = 70.0% | [39.7, 89.2] |
| E.1（N=20 预登记） | 19/20 = 95.0% | [76.4, 99.1] |
| **合并 n=30**（单独报告，不冒充前者的修订值） | **26/30 = 86.7%** | **[70.3, 94.7]** |

两批的差异检验：Fisher 精确检验双侧 **p = 0.095**，不构成异质性证据。
两批的 `config.json` 除身份字段外**逐块完全相同**（protocol、ppo、game 三个块 `==` 为 True），
运行器与协议模块 sha256 一致。因此 70% 与 95% 的差距是抽样波动。

**这正是 E.1 要回答的问题**：同一个 p 在 n=10 下可以抽出 70%，也可以抽出 95%。
confirmation 的 70% 不是 q=50 的性质，是一次抽样。区间宽度从 49.5pp 收到 **24.4pp**。

合并的正当性：同一冻结协议、同一运行器、互不相交的全新 seed、各自事前固定样本量、
无序贯停止。按预登记，**本轮到此为止，不再追加 seed**。

## 三、新出现的失败模式：development 通过、final 翻盘

E.1 首次出现候选在最终认证阶段失败——**这推翻了「瓶颈只在 discovery、validity 是免费的」这个说法**。

| 候选 | dev dReach/ΔW | 占阈值 | final dReach/ΔW | 超出 | 细化差（阈值 0.002） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0915 q60 s10020 | 0.009343 | 93.4% | 0.010055 | +0.55% | 7.1e-04 |
| **E1 q50 s10133** | 0.009817 | 98.2% | 0.010210 | +2.10% | 3.92e-04 |
| **E1 q50 s10136** | 0.009415 | 94.1% | 0.010349 | +3.49% | 9.34e-04 |

三例的数值细化差全部**低于** 0.002 的容差，失败的是 final 的绝对阈值。机制是结构性的：
`k_stop=1` 的 first-eligible 停止规则会在 dev 档**刚跌破 0.01 的那一刻**冻结权重，
因此被冻结的候选系统性地贴着门槛（三例的 dev 值都在阈值的 93–98%），
而 final 档（state 2 / effort 0.5 / GL 32）重算时有一部分会翻到 0.01 以上。

新协议下的合计：**24/26 = 92.3%** [75.9, 97.9]。

可选的缓解是给 development 停止加一点余量（例如 dev ≤ 0.009 才冻结），
代价是 discovery rate 下降。**本报告不建议改动已锁定的协议**——在看到不利结果之后
调整阈值，与之前拒绝用 restarts 移动闸门是同一个问题。正确做法是把这个率如实报告。

## 四、restart 预算必须按端到端算，不是按 discovery

restart 的单位是「一次 run → 一个**通过认证的**候选」。一个在 final 翻盘的候选不给你表格里的格子，
所以 k 要建立在端到端概率上。

| | k/n | 95% Wilson |
| --- | --- | --- |
| discovery | 26/30 = 86.7% | [70.3, 94.7] |
| conditional certification | 24/26 = 92.3% | [75.9, 97.9] |
| **端到端（restart 的口径）** | **24/30 = 80.0%** | **[62.7, 90.5]** |

后验 Beta(25, 7) 下的预测分布（点估计插值作对照）：

| k | 预测分布 | 插值 $1-(1-\hat p)^k$ | 高估 |
| ---: | ---: | ---: | ---: |
| 1 | 0.781 | 0.800 | +1.9 pp |
| 2 | **0.947** | 0.960 | +1.3 pp |
| 3 | **0.986** | 0.992 | +0.6 pp |
| 4 | 0.996 | 0.998 | +0.2 pp |

按表规模反推每格的 k（端到端后验）：

| 目标：整张表全部拿到认证候选 | m=2 | m=4 | m=8 |
| --- | ---: | ---: | ---: |
| ≥ 0.80 | k=2 | k=2 | k=3 |
| ≥ 0.90 | k=3 | k=3 | **k=4** |

n=30 把 k 的取值从「区间下端要 5 次、上端要 2 次」收敛到了可操作的 2–4 次。
**注意**：这个后验只属于 q=50、T=2。未测量过 p 的格子（任何新 horizon 或新经济参数）
不能套用，必须各自跑 pilot；无信息先验下预测分布只有 $k/(k+1)$。

## 五、B 段早停重启：按预登记的验证标准，**不采用**

confirmation 上 B 未过门与 discovery 失败完全重合（Fisher p = 0.016，但一格仅 2 样本）。
n=30 上重算：

| | 找到候选 | 无候选 |
| --- | ---: | ---: |
| B verifier_passed | 24 | 2 |
| B budget_exhausted | **2** | 2 |

Fisher 精确检验双侧 **p = 0.075**（odds ratio 12）。**4 条 B 未过门的 run 里有 2 条照样找到了候选**，
关联明显弱于 n=10 时的印象，且不显著。

预登记第四节写明「只有在更大样本上仍然成立，才把『B 未过门即重启』写进 restart 触发规则」。
**结论：不采用。restart 一律跑满完整预算。**

## 六、对 T=3 practical gate 的读法

| gate 条件 | 合并 n=30 的结果 | 点估计 | 区间 |
| --- | --- | --- | --- |
| q50 discovery ≥ 80% | 26/30 = 86.7% | **过线** | [70.3, 94.7]，下界低于 80% |
| P(final pass \| candidate) ≳ 90% | 24/26 = 92.3% | **过线** | [75.9, 97.9]，下界低于 90% |

两条的**点估计都过线**，这比 confirmation 单批（70%）的图景好得多。
但两个区间的下界都在门槛之下，n=30 仍不足以做显著性判定——预登记第六节已事先声明。
