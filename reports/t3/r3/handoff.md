# T3-R3 交接说明（给合作者）

本轮做了三件事：先诊断 `bw` 在 T = 3 上的十个失败（T3-R1 与 T3-R2 各自的失败合计）；然后提出两个有界的改进方案并实现；最后在 20 个全新的种子（70501–70520，q = 50 和 q = 60）上做一轮开发批次，三个臂：`bw`（对照，锁定设置原样）、`bwA`、`bwAB`，另加两个诊断 run（q = 60，种子 60518，不计入结果）。结论先说：**两个候选方案都达到了预先写好的开发目标（至少 38/40 通过，且每个 q 至少 18/20）；按预先登记的顺序提议 `bwA`。本轮没有锁定任何东西，也没有训练确认种子。**

## 1. 诊断：十个失败是什么

没有发现实现错误，也没有归入 (U)（无法解释）的失败；但 (K) 类的机制并未被证明（见下面）。十个失败分三类：

- **(F) 形成失败，1 个**：T3-R2 的 q = 60 种子 60518。第 3 阶段的策略始终没有形成对价差 d 的依赖（努力值几乎恒定，约 8.2），第二层隐藏单元饱和，带内与带外两部分梯度恰好方向相反。它不属于夹紧区间（S3 = 0）。
- **(K) 夹紧区间里的持续误差，8 个**：run 处于第 3 阶段的"夹紧区间"（S3 > 0.2：第 3 阶段最后 400 次更新里，带外起点上学习者的动作有超过 20% 落在动作夹紧值 1e-6 以下），失败量是持续的带内偏差或第 2 阶段的近零段。
- **(V) 最后一次迭代的波动，1 个**：T3-R1 的 q = 50 种子 50517。

夹紧区间在已有的 80 个 `bw` run 里占 30 个，并且和"带外节点处 Beta 均值落在 1e-6 的夹紧值"同时出现（30 个里 21 个在某个导出点出现，其余 50 个里 0 个）。但预先的预测之一（夹紧样本拿走不成比例的梯度份额）没有得到支持：夹紧样本和带外样本只占代理梯度的 0.3% 与 0.5–0.7%（它们在样本中的占比分别是 0.53–0.57 和 0.75）。所以区间是误差的原因还是只是一个标记，诊断阶段**没有检验**；候选 B 就是为了区分这一点。

回溯触发规则（第 3 阶段末的开发验证器增益 Δ > 0.005）在 80 个已有 run 里恰好触发 7 个，这 7 个全是失败，漏掉 3 个失败（两个第 2 阶段近零段，一个只有 RMSE 超限）；成本约 +3.7%。

## 2. 两个候选方案

- **A（`bwA`）**：在第 3 阶段末（本地更新 1600）读开发验证器的 Δ；若 Δ > 0.005（或 Δ、s、C 不是有限数，或 s ≤ 0），把第 3 阶段原地重新初始化一次并重训，冻结第二次的结果，第一次的产物移到 `attempt1/`，不覆盖、不删除。没触发的 run 与 `bw` 逐位相同。
- **B（`bwAB` = A + B）**：在第 3 阶段（两次尝试都是）对落在夹紧边界的动作改用截尾似然，其余不变。

## 3. 开发批次的结果

122 个 run（120 个开发 run + 2 个诊断 run）全部正常结束，没有基础设施故障。

| 臂 | q = 50 | q = 60 | 合计 | 精确 95% 区间（合计） | 达到目标 |
|---|---|---|---|---|---|
| `bw`（对照） | 18/20 | 19/20 | 37/40 | [0.796, 0.984] | 否（不参选） |
| `bwA` | 20/20 | 19/20 | 39/40 | [0.868, 0.999] | 是 |
| `bwAB` | 18/20 | 20/20 | 38/40 | [0.831, 0.994] | 是 |

- **按预先登记的顺序（先 `bwA`，再 `bwAB`），提议 `bwA`。**独立重算的程序给出相同的结果。
- `bwA` 比 `bw` 多的两个通过，是 q = 50 的两个种子（70508、70516）：触发器触发，第二次尝试通过；其余 38 个种子上两者逐位相同（精确 McNemar p = 0.5）。`bwA` 第一次尝试的通过数等于 `bw`（都是 37），符合 C-PAIR 的要求。
- **B 的因果读法是"混合"，不做因果结论。**预先写好的三个指标：S3 > 0.2 的第一次尝试数（`bwAB` 13，`bw` 与 `bwA` 都是 12；McNemar p = 1）没有变少；有第 2 阶段近零段的 run 数变少（1 对 3）；两个臂都没触发的 36 个种子上 η_3 配对差的区间 [-0.00008, 0.00064] 包含 0。
- **失败**：6 个失败 run（4 个种子），其中 5 个是 (K)、1 个是 (V)（`bwAB` 的 q = 50 种子 70520，RMSE 0.0543 对限值 0.05，恰是最后 16 次导出里最大的）。q = 60 的种子 70511（第 2 阶段近零段，28 个节点）在 `bw` 和 `bwA` 里失败，在 `bwAB` 里通过；它在第 3 阶段检查里看不见（Δ = 0.0040），A 够不到。
- **诊断 run（q = 60，种子 60518）**：第一次尝试（第 3 阶段）与 T3-R2 原始运行的第 3 阶段（64 个导出、第 3 阶段各行与检查、分箱图和状态）逐位相同；A 在两个臂里都触发（Δ = 0.1447）；两个第二次尝试都形成了策略（F(u1600) 为 54.1 和 50.2，阈值 26.78）并通过。

## 4. 成本

平均每个 run 的更新次数：`bw` 3800，`bwA` 3880（1.021 倍），`bwAB` 3920（1.032 倍）。触发时第 3 阶段训练两次，共 5400 次更新（1.421 倍）。实测墙钟：`bwA` 是 `bw` 的 1.081 倍，`bwAB` 是 1.201 倍；但各臂在同一个并发批次里按 `bwAB`、`bwA`、`bw` 的顺序跑，`bwA` 里 38 个与 `bw` 逐位相同的计算本身就慢了 1.065 倍，所以墙钟差的大部分看起来是运行环境造成的（由运行顺序和负载推断，没有直接测量），不是方案本身。

## 5. 偏差与限制

- **82 个 manifest 记录的是脏工作树**：启动后约 73 秒我往工作树里写了一个报告脚本（未跟踪文件），运行器把它算作脏树。已按 PI 的要求验证：5 个在干净树上重跑的 run（其中 2 个触发过，没有 `bw` run）与原始 run 逐位相同，并且标记严格随该文件的创建时间切换；122 个 run 仍是计入的记录。
- 第一次事后检查用了相对路径的 `--root`（`config_equals_plan` 显示 0/122），绝对路径重跑后 `config_equals_plan` 为 122/122（整体检查仍因 `clean_tree` 的 82 个失败而不通过，见上一条）；事后脚本在检查失败后没有停下，已改成遇到第一个非零退出就停。五个带 `--root` 的工具（launch、eval、checks、analysis、last16）现在拒绝相对路径。
- 每臂只有 40 个 run；`bwA` 的收益就是两个种子；A 只修复在第 3 阶段检查里看得见的失败，代价是触发时多训一遍第 3 阶段。
- 完整测试：1,819 通过，6 跳过，2 个 xfail，2 个已知失败（`test_registry_canonicalization`；`test_the_existing_launcher_is_unchanged`，自 T3-1.0 锁定改动 `protocols/` 起就失败）。

## 6. 没有做的事

按规定到 G2 停：没有锁定，没有训练确认种子（80501–80540），预先登记之后没有调任何东西。是否把 `bwA` 锁定并做确认（80 个 run 里至多 6 个失败，每个 q 的 40 个里至多 4 个失败），由 PI 在 G2 决定。若要改选 `bwAB`，只能给出 G1 回复 2.2 节里的某条理由。
