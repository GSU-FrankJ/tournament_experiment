## 4. Implementation (what the code does)

**4.1 Peak-focused starts.** `StartSampler.peak_set(t, half_width)` = the bins of the existing stage-t scheme (width `es_bin_width = 10`) whose interval intersects the open interval (-half_width, half_width) (a bin touching +-20 only at its edge is NOT in the set: [-30,-20] and [20,30] are outside; for half-width 20 the set is the four bins [-20,-10], [-10,0], [0,10], [10,20]); `peak_bin_probs` gives each peak bin `s / n_peak` and each other bin `(1 - s) / (n_bins - n_peak)`; `peak_focused` draws one `rng.random(n)`, maps it to the bin by `searchsorted(cumsum(p), u, side='right')` (last cdf entry pinned to 1.0, index clipped to the last bin), then draws the within-bin position from a second `rng.random(n)` exactly as `balanced` does. The bin counts of D_T are 40 (q = 50) and 44 (q = 60), so the locked bin-balanced scheme puts 4/40 = 0.100 and 4/44 = 0.091 of the episodes into the peak set. `balanced` draws its bins with `rng.integers`, so the `start` stream desynchronises from the baseline's at the first update by construction (this is a property of the arms, not a defect; the paired comparison is across different trajectories from update 1, exactly as for the R1 batch arms). `scheme = "bin_balanced"` (the default; `start_weights = null`) keeps the original code path. The scheme is stage-indexed: `Run.draw_starts(stage, n)` is called with the stage of the draw (`spec.T` in phase A, `stage` in phase P; the exploring-start call of phase C is reachable only in modes that refuse `start_weights`, so it always draws bin-balanced) and no stage number is hard-coded. `start_weights` is accepted for the modes `phase_A`, `phase_A_continue` and `phase_P` only (the modes whose phases draw exploring starts; `START_MODES`); it replaces the three `sampler.balanced` calls of the runner, in the same position and on the same `start` stream, so the roles draw (`rng.integers`) that follows is unchanged in kind and order.

**4.2 Censored likelihood.** `utils/beta_tail.py`: `log_betainc_small_x(x, a, b)` = log I_x(a, b) from the series I_x(a, b) = x^a / (a B(a, b)) * 2F1(a, 1-b; a+1; x) = x^a / (a B(a, b)) * sum_n [(1-b)_n / n!] [a/(a+n)] x^n, evaluated in float64 with `torch.lgamma` for log B and N = 12 terms, differentiable in (a, b). It is valid in the stated domain x * b <= 0.05 (c = 1e-6, so b <= 5e4); outside the domain it raises (loud, never silently inaccurate). Test: relative error against `scipy.special.betainc` over alpha in [1e-4, 10], beta in [1, 1000], c = 1e-6, required <= 1e-6; observed maximum 1.3e-12 (the independent review additionally compared with `mpmath.betainc` at 60 digits over alpha in [1e-4, 300], beta in [1e-4, 5e4]: maximum 4.6e-11). `row_log_prob(alpha, beta, actions, side, c)` returns the Beta log-density for every row and, for rows with side = -1, `log I_c(alpha, beta)` (P(A <= c)), for rows with side = +1, `log I_c(beta, alpha)` (P(A >= 1 - c)). Flags: in `collect_batch_v2` a raw draw `< c` sets side -1, `> 1 - c` sets +1 (the same raw-draw event the R1 D1 counters count), the stored action is the clipped one as before, the flag is stored per learner row (`batch["clamp_side"]`, int8), and rows whose action is a frozen-actor mean (stage-T continuation under `continuation_action_mode=mean`) are never flagged (the R1 D1 counters still count the discarded raw draw of such a row, so in a Phase-B-type run the flag count is not the sum of the `d1_*` counts; no R2b arm runs `clamp_likelihood = censored` in such a mode: wave A is `phase_A` with sampled continuation). With `clamp_likelihood = "censored"` the stored rollout log-prob of a flagged row is the censored log-mass, and the update uses `row_log_prob` for the ratio in `masked_actor_loss` and for the KL diagnostics; the density at the clipped value is never used for a flagged row. With `density` nothing in the pipeline reads the flags. A buffer without flagged rows takes the unchanged update path, so it is bit-identical to `density`. `n_censored_rows` per update is a column of `v2_updates.csv` in censored runs.

**4.3 Phase-P epochs.** `pathwise_update(agent, spec, d, stage, epochs, minibatch)`: `epochs` passes, each over one fresh permutation drawn as `agent.rng_mb.permutation(n)` (the PPO update draws the permutation of every epoch the same way, so the minibatch stream position after a 512-row update with E = 10 equals that of a PPO update), `n / minibatch` pathwise steps per pass (512 / 256 = 2, so 20 per update), each the existing `pathwise_step` (exact gradient of the expected terminal payoff, the actor Adam with its preserved state, clip 0.5, head row 1 restored bit-exactly after every step; no critic update). Logged per update: mean loss over the steps, mean and max pre-clip gradient norm, the FOC residual |dR/de| (mean, max) over the update's 512 rows evaluated after the last step, e(0) after the last step, the number of steps (`n_steps`). **Choice:** `pathwise_epochs = 1` with no minibatch (`null`) keeps the R1 single full-batch `pathwise_step` (no permutation, no stream use; bit-identical to R1's `A_detmean`); any other setting uses `pathwise_update`. In particular an explicit `pathwise_minibatch = 512` with E = 1 is NOT the R1 behaviour (it draws one permutation from the minibatch stream and permutes the rows; weights differ in the last digits): only `null` is the full-batch default. No arm uses it. The end-of-phase check of R1 (head, critic and critic Adam bit-identical to the parent) is kept. **Definitions that differ from R1's `A_detmean` log (state them when comparing):** `pathwise_step` logs `loss`, the FOC residual and `e0` at the PRE-step parameters on the full batch; `pathwise_update` logs `loss` as the mean of the minibatch pre-step losses over the 20 steps, and the FOC residual and `e0` AFTER the last step on all 512 rows (the owner's wording). Per-update trajectories of the P20 arms and of `A_detmean` are therefore not on the same time basis (a one-update offset for `e0` and the FOC residual): the analysis compares the end-of-phase states and the offline fixed-grid objective at the weight exports, and shows the logged curves only with this caveat. `n_minibatch_steps` (history, curriculum log, `v2_run_summary.json`) is the real number of exact-gradient steps (20 per update; found hard-coded to 1 by the review and fixed before the code commit); `n_steps` of `v2_updates.csv` is the same count.

## 5. Diagnostic of q = 50 seed 30510 (P2): plan and operational hypotheses

Tool `tools/v2/diag_seed30510.py` (reads only; writes under `results/v2_refine_r2b/diag_30510/`; no run, no change of any threshold). Data: `results/v2_T2_locked/confirmation_v2_0/q50/seed30510/` against the other 19 q = 50 runs of the block (the "pack") and the 20 q = 60 runs (second reference), all under the v2-t2-refine worktree. Contents of the report as in §3 of the prompt (peak trajectory, end-of-A profile, optimisation, sampling, three-way decomposition).

The hypotheses are made operational here, before any output of the diagnostic was read. What was known when this section was written: the owner's description of the run (peak error -0.1458, the eta_2 maximum on-path, smoothed-game share 0.279) and that the weight exports exist every 25 updates, u = 25, ..., 1600. Provenance of the order: this section's text was written at 07:03 UTC on 2026-10-04; the first output of the diagnostic-tool agent that was building the tool in a scratch directory was written at 07:20 UTC (file times of the draft and of the agent's outputs). The agent's final message, which the author saw before this file was committed, contained its verdicts under ITS OWN operationalisations of H1-H4 (chosen without these rules) and several of its numbers for seed 30510 (for example that the run was below the pack's band from about update 900). The rules below are the text written at 07:03; they were NOT changed after that message, and the committed tool applies them literally. Where a literal rule behaves awkwardly (for instance H1 takes the maximum over all exports, including the early transient), the result is reported as it comes out and the agent's readings go to the "post hoc readings" subsection. Notation: S_s(u) = (e2-hat(0; u) - e2*(0)) / e2*(0), the signed peak error of run s at the export of update u (evaluation-only closed form e2*); L_s(u) = (max_d e2-hat(d; u) - e2*(0)) / e2*(0) on the recovery grid (the location-free peak error, `pilot4_common.location_free`); p10_pack(u), p90_pack(u) = 10th / 90th percentile over the 19 pack runs at the same export (`numpy.percentile`, linear). out_S(u) = S_30510(u) < p10_pack(u); the "departure" u_leave is the first export from which out_S holds at every later export up to 1600 (undefined if out_S(1600) is false). Departure times are resolved to 25 updates.

| hypothesis | rule (all conditions) |
|---|---|
| H1: the peak never rose to the pack's level | max over all exports u of S_30510(u) < p10_pack(S, 1600) |
| H2: it rose, then decayed in the LR-decay window | not H1; out_S(1600); u_leave >= 1225 (in the pack's band at some export >= 1200) |
| H3: late excursion after a stable plateau | not H1; out_S(1600); u_leave <= 1200; and S_30510 is in the band (not out_S) at >= 16 consecutive exports ending at u_leave - 25 |
| H4: plateau at the pack's level of the peak height with an unusually rounded cusp | out_S(1600); L_30510(u) >= p10_pack(L, u) at every export u in 1225..1600; and the cusp rounding L - S of seed 30510 at 1600 exceeds p90_pack(L - S, 1600) |

A hypothesis is reported as "supported" when its rule holds, "not supported" when it does not, and "undetermined" when an input is missing; the hypotheses are not exclusive by construction (H4 is a statement about the shape of the end state, H1-H3 about the trajectory of S), and the report says which ones the data support jointly and which it cannot tell apart. Cases with out_S(1600), no H1, u_leave <= 1200 and no 400-update plateau are reported as "none of H1-H4 (early or unstable departure)". The same rules are also applied to each of the 20 q = 50 runs as the target against the other 19 (a table of how the rules behave on runs that passed), and every verdict sentence of the report is generated from the computed booleans. Any reading other than these rules (for example a strict form of H1 that starts at update 400, or a late-window form) is reported only in a subsection labelled "post hoc readings (not pre-registered)". The descriptive items of §3 of the prompt (dev-tier eta_2 and `would_have_fired` at every verifier call, KL, clip fraction, gradient norms, advantage SD, the concentration at d = 0, visitation of the stage-2 bins and the peak-set share, the D1 clamp counts, the three-way d = 0 gap) are reported without rules.

## 6. Metrics, criterion, bootstrap (§5, D3)

Final tier for every gate metric; recovery metrics are tier-independent. All differences are **arm - comparator**, paired by (q, seed); per q: median, mean, `n_better` out of 10, and 95% percentile bootstrap CIs of the mean and of the median. Every run is reported, failures included. Candidate: the stage-2 last iterate at the end of the phase (wave A: global update 1600; wave P: after the 200 updates). Tool: `tools/v2/refine_r2b_analysis.py`, reusing the R1 tools (`refine_analysis.py`, `pilot4_common.py`, ...). Reference roots are explicit arguments and are recorded in every output; a missing reference file stops the analysis.

**Bootstrap (D3).** 10,000 percentile resamples of the 10 paired seeds with replacement, `numpy.random.default_rng(20261004)`, one fresh generator per (q, statistic) in table order; the CI is the 2.5 / 97.5 percentiles of the resampled mean (respectively median).

**Primary metric:** the absolute signed peak error |(e2-hat(0) - e2*(0)) / e2*(0)| (improvement = negative difference; the baseline peak errors are negative, so this equals an increase of the signed error); the signed differences are reported as well. **Also:** the location-free peak error with its argmax d, RMSE_pos / e2*(0), tail mean and max, eta_2 / DW with the G-A verdict and the dev - final difference (the G-N part), the symmetry error, sigma_2(0), the smoothed-game share of the d = 0 gap. **Tail statistics per arm and q:** max |peak error| over the 10 seeds, the number of runs with |peak error| <= 0.05, the number of runs with eta_2 / DW > 0.004 (the G-A margin). **Optimisation:** KL, clip fraction, gradient norms, number of steps, wall time. Wave A additionally: the peak-set visitation share and the D1 clamp counts (and, for `A_censored`, `n_censored_rows`, the first update with a flagged row, the tail profile e2-hat on |d| >= 2q and the off-path Delta_2). Wave P additionally: the loss and FOC-residual trajectories and the number of steps.

**Definitions of verdicts (v2.0):** G-A = eta_2 / DW <= 0.005 and RMSE_pos / e2*(0) <= 0.05 and tail mean / e2*(0) <= 0.02 (final tier); G-N part = |dev - final| <= 0.001 for eta_2 / DW; the stage-2 criterion's gate is G-A with its G-N part.

**Per-arm criterion (descriptive, for the owner's decision, not a gate).** (a) The bootstrap CI of the mean paired difference of the primary metric against the arm's baseline / control excludes 0 in the improving direction at **both** q; (b) no run that passed G-A and its G-N part under the baseline fails it under the arm. Both parts are reported separately, with the tail statistics next to them. For wave A the baseline is `parents_A`; for wave P the primary comparison of the pathwise arms is the PPO control with the same LR, and of `A_ctrl200_lr3e-4` the parent u1600 candidate; all other comparisons are reported without a verdict.

**Reading `A_censored` (from the R1 D1 data, written before any R2b run).** The mechanism acts only on rows whose raw draw fell below c = 1e-6 (or above 1 - c). In the baseline `parents_A` runs the total number of such learner draws over the 1600 updates is 0 for q = 50 seed 10502 and q = 60 seed 10506, and 3 to 65,787 for the other development seeds, with a first flagged update between 189 and 1157 (q = 50) and between 217 and 834 (q = 60) (`results/v2_refine/parents_A/q*/seed*/v2_updates.csv`, `d1_L_s2_lo + d1_L_s2_hi`; the per-seed table is `results/v2_refine_r2b/preflight/parentsA_d1_flag_counts.txt`). For a seed with no flagged row the censored run is bit-identical to its baseline (paired difference exactly 0); for the others it is bit-identical up to the first flagged update. The analysis therefore prints each seed's first flagged update and total flagged-row count next to the paired difference, and counts exact zeros as "not better" (`n_better` is the number of strictly improving differences; `n_zero` is reported), so that a null result is not read as "the mechanism does nothing".

**Statements the analysis will make:** the peak arms' start stream desynchronises at update 1 by construction; `A_censored` is bit-identical to its baseline until the first update whose buffer contains a flagged row (the first such update is recorded per run) and diverges from then on; the one-factor pairing is by (q, seed) of trajectories that are not step-identical after divergence, so a difference of one seed can reflect trajectory noise (the across-seed spread, not a per-seed attribution, is the evidence).
