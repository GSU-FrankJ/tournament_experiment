# MS-R1 pilot (P2): results of the 120 runs

Date: 2026-10-07. Branch `ms-r1`. The pilot is the six-arm wave of addendum 1 of `02_preregistration.md` (the five rule arms of D6 and the budget-matched control `MS_base2400`), 20 runs per arm (q in {50, 60} x seeds 10501-10510), plus the 20 `MS_base` runs of P1 (`results/ms_r1/base`, the arm that reproduces `parents_A`). Everything below is read from `results/ms_r1/analysis/` (written by `tools/ms/r1_analysis.py`, checked by `tools/ms/blind_criterion.py`) and every table generated by `reports/ms/r1/report_scripts/pilot_tables.py` has its command under it (the two tables of sections 1 and 3 are written by hand from the launch record, the launch checks and the analysis CSVs; the `path` column names the source). **Only section 2, first table, is the pre-registered criterion; everything else is descriptive**, and the secondary table of section 2 is descriptive by decision of the PI. An interval that contains 0 with 10 seeds does not show that a mechanism has no effect, and an interval that excludes 0 is one of many printed here (a `*` marks it); no multiplicity correction is applied. Nothing in this file selects an arm or changes a protocol: the decision is the PI's.

Reading the tables. `arm - baseline` differences of |peak error| (`stage2_peak_rel_err_abs`, the primary metric, final tier) are negative when the arm is better. "Signed peak error" is `(e_hat_2(0) - e_2*(0)) / e_2*(0)` at the terminal-stage freeze: negative = the learned peak is below the closed form. `parents_A` is v2.0's end of Phase A (1600 updates, 1200 + 400 decay); `MS_base` is identical to it in the terminal stage (check C-MS1, `03_checks.md`), so its paired differences are 0 by construction. The five rule arms train 2000 updates at 3e-4 plus a 400-update landing (2400 terminal-stage updates, 1.5 times `parents_A`); `MS_base2400` has the same 2400 updates without the rule and the stratified sampler.

## 7. Anomalies and notes

1. **One G-A failure in 140 terminal-stage runs**: `MS_s35a0` q = 50 seed 10508, eta_2/DW = 0.005054 (limit 0.005), eta on the development tier the same value (G-N holds), RMSE_pos 0.0417 and tail mean 0.0095 pass, |peak error| 0.0196. It is the only part-(b) violation of the table (against `parents_A` and against `MS_base2400`: both pass this run, eta_2/DW 0.00114 and 0.00043).
2. **Smoothed-share outliers.** |share| > 2 in 5 runs (`MS_base2400` q = 50 seed 10503 10.5; `MS_rule` q = 50 seed 10505 8.7; `MS_s35a0` q = 50 seed 10507 6.8 and q = 60 seed 10501 -159; `MS_s35a5` q = 50 seed 10509 2.1), all with |peak error| < 0.015 (the denominator g_2(0) - e_hat(0) is near 0); means in `decision_inputs.csv` are therefore not used, medians are.
3. **R0 ratio outliers**: three runs, section 5.3.
4. **Start-share flags**: 3 of 1860 tests (about 5 expected), section 1.
5. **One stage-1 cap**: `MS_rule` q = 60 seed 10507 did not stop in stage 1 (cap 600, landing at local 601, 1000 updates).
6. **`MS_base`'s terminal-stage would-fire record** is at rho_2 = 0.03 (the P1 launch error); the recomputed value is in `03_checks.md`.
7. **Reviewer's scratch run.** The independent reviewer of the code ran one `MS_base2400` run (q = 50, seed 10501) in a scratch directory outside `results/`; it is not part of this analysis.
8. **Comparator quantities not stored**: `parents_A` has no smoothed-game share, no stage 1 and no rule record; `rehearsal_v2_0` has no development-tier R_1 at the final tier (`analysis_info.json`, `a3_not_stored_by_design`).
