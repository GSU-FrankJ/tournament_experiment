## 2. Confirmation design

- q in [50, 60]; seeds 60501-60520 (the same 20 seeds at both q): 40 runs, arm `bw` only; run names `t3r2_q{q}_s{seed}_bw`; directories `results/t3_r2/confirmation/q{q}/seed{seed}/bw`.
- Each config is T3-R1's `bw` config of the same q with only these fields set: `seed`, `run`, `record.run`, `record.seed`, `record.output_dir`, `pilot` (`pilot` = "t3_r2").
- Seeds never trained: 40501-40520, 10501-10530, 30501-30520, 50500-50520 (except the four audit re-runs).

## 3. Gates (T3-R1's, inclusive `<=`, full float64 precision)

| Gate | Criterion |
|---|---|
| G-A | `eta_T_over_dw` <= 0.005, `rmse_pos_T_over_eT0` <= 0.05, `tail_mean_T_over_eT0` <= 0.02 (final tier) |
| G-F | `Gmax_full_over_dw` <= 0.01 (final tier) |
| G-N | development minus final: abs diff of `eta_T_over_dw` <= 0.001 and of `Gmax_full_over_dw` <= 0.001 |

**Run pass:** exit code 0; the process-global RNG assertion is ok; a valid evaluation (final and development tier); and G-A and G-F and G-N.

## 4. Confirmation rule

- the confirmation passes iff at least 36 of the 40 runs pass, and at least 17 of 20 at q = 50 pass, and at least 17 of 20 at q = 60 pass; otherwise it fails.
- Rationale: the confirmation must reproduce T3-R1's development pass rate (36 of 40), with neither q below 17 of 20.

## 5. Failure counting

- every planned run is reported; no seed is replaced or re-drawn.
- Infrastructure failure, only if one of these holds:
  - a negative return code (a signal, e.g. SIGKILL)
  - an out-of-memory kill recorded in the kernel log or the run's log
  - OSError ENOSPC recorded in the run's status.json or traceback
- Ledger: `results/t3_r2/confirmation/infra_events.json; the analysis tool and the blind tool both read it`.
- Re-run: the attempt is moved to results/t3_r2/crashed/ and the run is repeated once into the original path; if the repeat also fails for an infrastructure reason the confirmation stops without a verdict and that run is counted neither way.
- Other failures: any other nonzero exit, and any global-RNG violation, is a failed run.
- Evaluation problems: an evaluation error, or an evaluation with valid = False, counts as a failed run unless a re-run of the locked evaluator on the same weights succeeds; the re-run is reported; a completed run is never re-trained.

## 6. Reported, deciding nothing

- pass counts per q with exact Clopper-Pearson 95 % intervals
- per failing run the diagnosis of reports/t3/r1/04_t3_results.md section 4.1 plus the A7 analysis
- the near-zero stretches of all 40 runs
- the pass rate pooled with T3-R1's 40 development runs (descriptive)
- the gate values set against T3-R1's

If the confirmation fails: nothing is changed or tried; the PI decides the next step.
